## Honourable mentions (3)

- **cosanlab/py-feat** (389 stars, MIT code but model weights carry separate terms, 20 releases, docs, CI, PyPI): the best-maintained way to compute PSPI from action units offline and check SpineSense's blendshape grimace score. It is a facial-expression toolbox, not a pain detector, and the weights licence needs checking. The only released chronic-low-back-pain protective-behaviour code is Mvrjustid/EmoPainChallenge2020 (21 stars, MIT, last push 2020), which is exactly on target but dormant.
- **Gautham495/react-native-nitro-pose-exercises** (10 stars, MIT, 28 releases, CI/publish workflows): the files call it the closest design analogue to `js/core/engine.js` (rep and hold state machines, angle-based form rules, "get in position" gating). Held back by being young with one author, so community and long-run maintenance are unproven.
- **MSD-IRIMAS/DeepRehabPile** (18 stars, GPL-3.0, 5 releases, PyPI, pytest, Docker): benchmark code for nine architectures across 60 skeleton-rehab datasets with fixed folds, and the closest thing in the set to rehab exercise-quality assessment done properly. GPL-3.0 means it can only live in offline `ml/`, and the star count is low.

## The gap

None of these projects combines what SpineSense puts in one browser page. They are either infrastructure (IMU fusion firmware, gait algorithms, multi-camera mocap, musculoskeletal modelling) or single-pillar research code, and the candidate notes themselves say no mature open-source rehab coaching app turned up (closest are knee-form-check at 0 stars and 8-9 test subjects, open-posture at 16 commits and posture only, and nitro-pose-exercises with one author). Specifically, none pairs a single on-device webcam tracker with optional low-cost BLE back sensors that give a true dual-inclinometer lower-back angle, none then uses that sensor angle as a label source for camera-only models, and none wraps the result in a rehab-specific safety layer: red-flag screening for cauda equina signs, dated and expiring clinician clearances, pain-rating-driven plans, and a response ladder that eases off or stops when a discomfort detector (voice, range drop, slowing, guarding, shaking, bracing, plus an opt-in facial-strain signal that never acts alone) fires against the user's own baseline. None offers this with local-only storage and a CSP-enforced privacy model. The honest caveat, taken from SpineSense's own README: the combination is unvalidated (thresholds were tuned on simulated movement and the grimace score has not been validated for pain), so the gap is also a validation debt that mobgap, OpenSim and freemocap-style methods are best placed to help close. Confidence that the gap is real within this candidate set: medium-high. Confidence that it exists across all of GitHub: lower, because the set comes from keyword searches and is not exhaustive. Also note a naming clash with NickSakito777/spinesense (an unrelated five-IMU garment project).
