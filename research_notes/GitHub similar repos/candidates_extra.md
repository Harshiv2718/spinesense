**How these were found and checked**
- 147 GitHub REST search queries (`/search/repositories`, sorted by stars, about 7 s apart). They covered topic searches (`topic:physiotherapy`, `topic:web-bluetooth`, `topic:imu-sensor`, ...), README searches (`KIMORE in:readme`, `EmoPain in:readme`, `UNBC in:readme pain`, `BioVid in:readme`), dataset names, IMU and fusion terms, pain and AU terms, and validation terms. On top of that: web searches, the Awesome-AQA list, and PyPI metadata.
- **Stats** (stars, forks, last push, licence, language) come from the GitHub API search results or `/repos/OWNER/REPO`, retrieved on 2026-10-17. Push dates are UTC.
- **Maturity** comes from each repo's GitHub page: root file tree, release count, commit count, and the names of its `.github/workflows` files. I also read the first part of most READMEs.
- **Licence**: the SPDX id GitHub reports. Where GitHub says NOASSERTION or none, I read the LICENSE file or README and say what it states. Where there is nothing, the table says "licence not stated".
- **Layer** uses the stage names in `docs/architecture.md`: L1 capture / sensors, L2 signal, L3 calibration, L4 features, L5 inference (rules, models, discomfort), L7 experience, ML pipeline, validation pipeline, hardware pipeline.

## Strongest new finds

The best-built finds are mostly infrastructure: libraries SpineSense would use rather than whole apps. That is because no mature open-source rehab coaching app turned up.

1. **xioTechnologies/Fusion (with dlaidig/vqf).** Proven sensor fusion under MIT, with CI and Python packages. It could replace or check the firmware's own fusion, and the same filter can re-fuse raw logs offline in `ml/`.
2. **mobilise-d/mobgap (with pfizer-opensource/scikit-digital-health).** Validated, tested, documented reference code for a single lower-back IMU (Apache-2.0 / MIT). It is the model to copy for `docs/validation.md`. SKDH already has sit-to-stand detection.
3. **MSD-IRIMAS/DeepRehabPile.** The actual code behind the Rehab-Pile/LITEMV plan in architecture.md: PyPI package, pytest CI, Docker, fixed folds over 60 rehab datasets. It is GPL-3.0, so keep it in offline `ml/`.
4. **SlimeVR/SlimeVR-Tracker-ESP.** Mature ESP32 multi-IMU firmware (17 releases, PlatformIO, CI, dual Apache/MIT). A good model for the planned firmware CI and the IMU driver layer.
5. **freemocap/freemocap.** The strongest camera validation tool (10k+ stars, tested, released). Pair it with spm1d and pyCompare for the statistics.

Two more fall outside that top five. For the pain layer, cosanlab/py-feat (MIT code, CI, 20 releases) is the best-maintained way to compute PSPI offline, and the Mvrjustid EmoPain repos are the only released code built on chronic low-back-pain protective behaviour. They are small, but exactly on target.

Two zero-star repos are also worth reading now:
- **damihr/knee-form-check** has an almost identical browser architecture (MediaPipe, LITE 1D-CNN in ONNX Runtime Web, leave-one-subject-out evaluation).
- **NickSakito777/spinesense** is a separate IMU project that already uses the name "SpineSense".
