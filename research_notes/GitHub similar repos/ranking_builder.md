# Builder ranking: top repos for a solo developer building SpineSense

Lens: how much a solo builder can learn from and reuse. Weights: clean architecture, reusable components, permissive licence, and a direct match to a SpineSense layer (browser pose pipeline, IMU firmware and fusion, rehab ML training, validation). All facts come from `candidates_initial.md` and `candidates_extra.md`; I did not open the repos, so confidence is stated per row.

## Honourable mentions (3)

- **Gautham495/react-native-nitro-pose-exercises** (10 stars, MIT): the closest design analogue to `js/core/engine.js` (rep and hold state machines, angle-based form rules, "get in position" gating, 28 releases, CI). Not in the top 5 because it is young, single-author and mobile-native (Apple Vision / ML Kit), so read its state machines to harden the engine rather than reuse code. Confidence: medium.
- **Mvrjustid/EmoPainChallenge2020** (21 stars, MIT): the only released code built on protective-behaviour detection in chronic low-back-pain patients during exercise (with BodyAttentionNetwork, 8 stars, MIT, as a learned guarding detector from joint angles). Use it to define validation targets for the discomfort detector; held back because the data is on application and one sibling repo says its code is not directly runnable. Confidence: medium.
- **damihr/knee-form-check** (0 stars, licence not stated): near-identical browser stack to SpineSense's plan (MediaPipe, 1D-CNN in ONNX Runtime Web, leave-one-subject-out results in EVALUATION.md) and the candidate file says to read it before building `js/ml/`. Not ranked because it was created 2026-10-15, its accuracy comes from only 8-9 people, and with no licence you can learn from it but not copy it. Confidence: low to medium.

## The gap

None of these projects joins the pieces SpineSense joins. mobgap and scikit-digital-health validate a single lower-back IMU, but for gait and mobility rather than exercise coaching; knee-form-check runs a browser pose pipeline with ONNX Runtime Web, but for squats and lunges, with no IMU and no pain or discomfort layer; the EmoPain repos model protective behaviour in chronic low-back-pain patients, but as offline challenge code on application-only data, not a live coach; open-posture (Apache-2.0) shares the personal-baseline, not-a-medical-device stance but nudges desktop posture rather than coaching rehab exercises; react-native-nitro-pose-exercises has rep and hold state machines with start-position gating but no sensors, discomfort detection or safety gates; and NickSakito777/spinesense is a five-IMU garment with offline fusion only. What SpineSense does that none of them describes: (1) it uses a back-worn dual-IMU lumbar angle (the clinical dual-inclinometer method) as the answer key to train camera-only lumbar estimation, with exercise-time clips pairing landmarks and sensor angles; (2) it fuses a movement-first discomfort signal against the user's own baseline, with the facial signal advisory only; (3) it puts plain, tested safety gates (emergency lock, dated clinician clearances, leg-symptom check, next-day level-up gate) above every model; and (4) it runs all of it as a static, local-first browser page where video never leaves the device. Confidence: medium. This rests on the candidate files' summaries, not on reading each repo's source, and the claim that others lack safety gating is inferred from silence in those summaries.
